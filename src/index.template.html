¿Qué hace exactamente?

formato

Genera un archivo PCK tipo 3 (big endian, el que leen PS3 / Xbox 360 / Wii U) con esta estructura interna, la misma que produce PCK Studio:

0 (InfoFile)parámetros PACKID y PACKVERSION
localisation.locnombre del pack (IDS_DISPLAY_NAME) y nombre de cada skin
dlcskin########.pngla textura + DISPLAYNAME, DISPLAYNAMEID, THEMENAME, ANIM, GAME_FLAGS, FREE y, si hay modelo 3D, una entrada BOX por caja

Cabecera: int32 pckType, tabla de parámetros (LUT), lista de entradas (tamaño, tipo, nombre) y contenidos en formato UTF-16 con el endianness del pack.

El valor ANIM se ajusta según el modelo: 0x00000000 para skins 64×32 clásicas, 0x00040000 para modernas de brazos anchos y 0x00080000 para Alex / slim.

La geometría viaja en el parámetro BOX: TIPO X Y Z ANCHO ALTO FONDO U V (más máscara de armadura, espejo e inflado en versiones nuevas). Ese formato solo existe desde la TU7 y necesita XMLVERSION 2 o 3 en la cabecera del pack.

Consejos rápidos

• Usa skins 64×64 con transparencia real; el juego no rellena huecos.
• Mantén cada PNG por debajo de 32 KB; imágenes muy pesadas pueden colgar la consola.
• Las skins 2:1 (64×32) deben ir con modelo «Clásico».
• Para Alex / slim elige «Moderno fino»; PS3 renderiza brazos de 4 px, así que el resultado es aproximado.
• Puedes abrir un .pck oficial: sus skins se cargan en la lista y se pueden reexportar junto a las tuyas.
• Modelo 3D: suelta un .bbmodel de Blockbench (con su textura dentro) y se convierte a cajas BOX de LCE. LCE solo entiende las 6 partes del jugador y sus 6 capas: los cubos se emparejan por su nombre o por la carpeta que los contiene (head, body, right_arm…), los que no encajan se ignoran y las rotaciones se pierden.

A Si la armadura se ve mal

El juego dibuja la armadura sobre el modelo estándar (cabeza 8×8×8, cuerpo 8×12×4, brazos y piernas 4×12×4), no sobre tus cajas. Si agrandas una parte o llevas capas, el casco o el peto se quedan dentro de tu geometría y se ve raro.

¿Se puede pasar un pack de Java tal cual?

honestidad

No directamente. Minecraft de PS3 no usa un PNG por bloque: guarda las texturas en atlas (terrain.png, items.png, particles.png, art/kz.png, misc/explosion.png…) con una rejilla y un orden fijos que no coinciden con los de Java ni Bedrock. Además necesita colours.col (tintes de bioma), modelos, animaciones… Un zip de Java no trae nada de eso, así que «convertirlo» tile a tile daría un pack roto.

Lo que sí funciona (y hace esta pestaña): usar un pack de LCE como base y sustituir sus texturas por las tuyas, respetando el layout. Es el flujo real de los creadores de packs: extraer los atlas, editarlos y volver a empaquetarlos.

  1. Consigue un pack base (x16.pck) — con PCK Studio o desde el propio juego.
  2. Pulsa Exportar los PNG del pack (.zip) y edita terrain.png, items.png… en tu editor.
  3. Vuelve a soltar el zip aquí: se sustituyen solo las texturas que coincidan.
  4. Descarga el .pck y instálalo en la PS3.

Rutas que se emparejan: assets/minecraft/textures/block/x.png → textures/blocks/x.png, …/textures/item/x.png → textures/items/x.png, …/textures/entity/x.png → mob/x.png, y coincidencia por nombre de archivo (p. ej. terrain.png).

Privacidad: todo el proceso (lectura de ZIP, escalado y escritura del .pck) ocurre en tu navegador. No se envía ningún archivo a Internet.
